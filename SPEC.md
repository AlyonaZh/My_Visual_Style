# ТЗ: «Мой визуальный язык»

Техническое задание для Claude Code. Положи файл в корень репозитория. Работай по этапам из раздела 10: после каждого этапа покажи результат и дождись подтверждения. Если что-то в ТЗ неоднозначно, спроси, а не додумывай.

---

## 1. Что это за сервис

Веб-сервис для начинающих иллюстраторов и художников. Он помогает понять, какие художественные приёмы им близки.

Сервис устроен как курс из приёмов в фиксированном порядке. На странице приёма человек:

1. читает справку: что это за приём, откуда он взялся, у кого посмотреть;
2. пробует приём сам в любом медиуме: на бумаге, в графическом редакторе, на фото, в коллаже. Если хочется быстрее, можно загрузить свою работу в нейросеть и применить к ней готовый промт;
3. возвращается и ставит оценку «насколько этот приём — мой» по шкале от 1 до 5, по желанию пишет заметку.

Рисование происходит вне сервиса. Сервис не загружает и не хранит изображения пользователя.

**Первая версия содержит один приём — «Глитч».** Остальные приёмы будут добавляться позже как данные, без изменения кода. Поэтому код с самого начала рассчитан на список приёмов, а не на одну страницу.

## 2. Ключевые решения

| Параметр | Решение |
|---|---|
| Название | «Мой визуальный язык» |
| Язык интерфейса | Русский |
| Аккаунты | Нет. Прогресс хранится в `localStorage` браузера |
| Бэкенд | Нет, статический сайт |
| Хостинг | GitHub Pages, деплой через GitHub Actions |
| Темы | Светлая и тёмная, переключатель в шапке |
| Оценка | Шкала 1–5 с подписями и необязательная заметка до 500 символов |
| Промты | Применяются к загруженному в нейросеть изображению. Две версии: английская и русская, у каждой кнопка-иконка копирования |
| Примеры изображений | Автор кладёт файлы в репозиторий сам |
| Стиль | Чистый и минималистичный (раздел 7) |

## 3. Стек

- Vite + React + TypeScript.
- Роутинг: `react-router-dom` с `HashRouter`, чтобы на GitHub Pages не было 404 при перезагрузке.
- Стили: обычный CSS с CSS-переменными. Без Tailwind и UI-библиотек.
- Шрифты из Google Fonts с кириллицей: Onest (интерфейс и заголовки), JetBrains Mono (промты и мелкие служебные подписи).
- Никаких внешних API, аналитики и трекеров.
- Тесты: Vitest для модуля хранилища.

Структура:

```
src/
  data/techniques.json     — контент приёмов
  lib/storage.ts           — чтение и запись прогресса
  lib/theme.ts             — тема
  components/              — Header, ThemeToggle, CopyButton, RatingForm, ...
  pages/                   — TechniquePage, NotFound
  styles/tokens.css        — цвета, шрифты, отступы
public/
  examples/                — картинки-примеры (кладёт автор)
```

## 4. Данные

### 4.1. Приём (`src/data/techniques.json`)

Массив объектов такого вида:

```ts
type Axis = "color" | "texture" | "form" | "composition";

interface Technique {
  id: string;            // латиницей, kebab-case, используется в URL: "glitch"
  order: number;         // порядковый номер в курсе
  title: string;         // «Глитч»
  axis: Axis;            // основная ось, показывается меткой у заголовка
  summary: string;       // главное описание, 1–2 предложения
  history: string;       // откуда приём взялся, 1–3 предложения
  task: string;          // задание
  tips: string[];        // 2–4 коротких подсказки
  duration: string;      // «15–30 мин»
  artists: { name: string; note: string }[];
  prompt: { en: string; ru: string };
  promptIntro: string;   // текст над промтами
  promptNote: string;    // текст под промтами
  image?: { src: string; alt: string; caption: string }; // src относительно public/
}
```

Подписи осей в интерфейсе: color — «Цвет», texture — «Фактура», form — «Форма», composition — «Композиция».

Общее количество приёмов в курсе задаётся константой `COURSE_LENGTH = 12` и показывается в шапке («приём 1 / 12»), даже если в JSON пока только один приём.

### 4.2. Контент первого приёма

Перенеси в JSON дословно.

- **id:** `glitch`
- **order:** 1
- **title:** Глитч
- **axis:** texture
- **summary:** Эстетика сбоя: смещённые цветовые каналы, полосы, разорванные пиксели. Ошибка становится выразительным средством и напоминает, что изображение цифровое.
- **history:** Предшественники приёма появились ещё в 1960-х: Нам Джун Пайк искажал телевизионное изображение магнитами. Как самостоятельное направление глитч-арт сложился в конце 1990-х и в 2000-х вместе с сетевым искусством и электронной музыкой, а в 2010-х получил свои фестивали и теорию.
- **duration:** 15–30 мин
- **task:** Примени глитч к своей работе в любом медиуме: на бумаге, в графическом редакторе, на фото, в коллаже или даже в вышивке. Важно попробовать самому и почувствовать, откликается ли тебе этот приём.
- **tips:**
  - На бумаге: нарежь распечатку полосками и собери со смещением.
  - В редакторе: сдвинь цветовые каналы или часть изображения в сторону.
  - Сохраняй узнаваемость: сбой интересен, когда видно, что сломано.
- **artists:**
  - Роза Менкман — теоретик и практик глитч-арта
  - Филлип Стернс — глитч-узоры на тканях
- **promptIntro:** Хочешь ускориться? Загрузи свою работу или фото в нейросеть, которая умеет редактировать изображения, и добавь этот промт.
- **prompt.en:** Apply a glitch art effect to this image: shift the RGB color channels slightly apart, add several horizontal displacement bands, a few pixel-sorting streaks and digital compression artifacts. Keep the subject, composition and original style recognizable.
- **prompt.ru:** Добавь к этому изображению эффект глитч-арта: слегка раздвинь цветовые каналы RGB, добавь несколько горизонтальных полос сдвига, пару полос сортировки пикселей и цифровые артефакты сжатия. Сохрани узнаваемыми объект, композицию и исходный стиль.
- **promptNote:** Английская версия обычно работает точнее. Результат нейросети — отправная точка: посмотри, что в нём твоё, и доработай.
- **image:** `{ "src": "examples/glitch.webp", "alt": "Пример приёма «Глитч»", "caption": "Пример приёма «Глитч»" }`

### 4.3. Прогресс (`localStorage`)

Ключ `my-visual-language:v1`, значение — JSON:

```ts
interface Progress {
  version: 1;
  entries: Record<string, {   // ключ — technique.id
    rating: 1 | 2 | 3 | 4 | 5;
    note: string;             // может быть пустой, до 500 символов
    updatedAt: string;        // ISO-дата
  }>;
}
```

Требования к `src/lib/storage.ts`:
- каждое чтение и запись в `try/catch`;
- если хранилище недоступно или данные битые, сервис работает с пустым прогрессом и показывает в подвале строку «Прогресс не сохраняется в этом браузере»;
- функции: `loadProgress`, `saveEntry`, `clearProgress`;
- юнит-тесты: пустое хранилище, битый JSON, недоступный `localStorage`, сохранение и чтение записи.

Тема хранится отдельно, ключ `my-visual-language:theme`, значение `"light"` или `"dark"`.

## 5. Экраны

### 5.1. Маршруты

- `/` — перенаправляет на первый приём без оценки, а если все оценены, на первый приём.
- `/technique/:id` — страница приёма.
- Неизвестный `id` — страница «Такого приёма нет» со ссылкой на первый приём.

### 5.2. Шапка

Слева: название «Мой визуальный язык» и рядом мелким моноширинным шрифтом «приём N / 12». Справа: переключатель темы.

Под шапкой тонкая горизонтальная линия на всю ширину контента. Полосы прогресса нет.

### 5.3. Переключатель темы

- Две кнопки в общей капсуле: «Светлая» и «Тёмная». Активная залита цветом текста, неактивная прозрачная.
- При первом визите тема берётся из настроек системы (`prefers-color-scheme`), и соответствующая кнопка показана активной.
- После нажатия выбор сохраняется и применяется при следующих визитах.
- Тема ставится атрибутом `data-theme` на `<html>`. Чтобы не было вспышки другой темы при загрузке, атрибут выставляется маленьким инлайн-скриптом в `index.html` до загрузки React.
- Кнопки имеют `aria-pressed`, группа — `aria-label="Тема оформления"`.

### 5.4. Страница приёма

Блоки сверху вниз:

1. **Шапка приёма.** Метка оси: цветная точка и подпись («Фактура»). Ниже огромный заголовок (около 128 px на десктопе, адаптивно уменьшается). Без эффектов и анимации. Под ним `summary` крупным текстом (22 px) и `history` текстом поменьше, приглушённым цветом. Ширина текста не больше ~640 px.
2. **Пример.** Картинка из `image.src` на всю ширину контента, со скруглением 4 px, подпись `image.caption` под ней мелким приглушённым текстом. Если поля `image` нет или файл не загрузился, на его месте рамка с пунктирной границей и надписью «Пример появится позже», пропорция 16:7, чтобы вёрстка не прыгала.
3. **Задание.** Раздел в две колонки: слева подпись «Задание · {duration}», справа `task` крупным текстом и список `tips` приглушённым цветом. Без маркеров-точек, с отступами между пунктами.
4. **У кого посмотреть.** Слева подпись, справа имена художников в две колонки: имя обычным весом, под ним `note` мельче и приглушённо. Только текст, без ссылок и картинок.
5. **Быстрее с нейросетью.** Слева подпись, справа `promptIntro`, затем две карточки рядом: «English» и «Русский». В каждой карточке сверху подпись языка и кнопка копирования, ниже текст промта моноширинным шрифтом. Под карточками `promptNote` мелким приглушённым текстом.
6. **Твоя оценка.** Отделена сверху толстой линией (2 px, цвет текста). Слева подпись «Твоя оценка», справа форма (раздел 5.6).

Разделы 3–5 разделены тонкими линиями. Двухколоночная раскладка: сетка из 12 колонок, подпись занимает 3, содержание 9. На ширине меньше 720 px подпись встаёт над содержанием, карточки промтов и колонки художников идут друг под другом.

### 5.5. Кнопка копирования

- Иконка из двух наложенных скруглённых квадратиков (контурная, 18 px), без текста. Область нажатия не меньше 36×36 px.
- `aria-label="Скопировать промт на английском"` или «…на русском», `title="Скопировать"`.
- После успешного копирования иконка на 2 секунды меняется на галочку, а скрытый `aria-live` элемент объявляет «Скопировано».
- Копирование через `navigator.clipboard.writeText`. Если не вышло — выделить текст промта, чтобы человек скопировал сам.

### 5.6. Форма оценки

- Заголовок-вопрос «Насколько этот приём — твой?» (26 px).
- Пять вариантов в ряд, каждый — карточка с цифрой и подписью: 1 «Совсем не моё», 2 «Скорее нет», 3 «Нейтрально», 4 «Скорее да», 5 «Очень моё». Выбранная карточка залита цветом текста, текст на ней цвета фона. Реализовать как группу радиокнопок, чтобы работали стрелки клавиатуры. На узком экране подписи уменьшаются, но не исчезают.
- Поле заметки: подпись «Заметка, необязательно» над полем. Поле с рамкой 1 px, скруглением 8 px, лёгкой заливкой, высотой от 120 px. При фокусе рамка темнеет до цвета текста.
- Пример внутри поля — плейсхолдер бледного цвета: «Например: сдвиг каналов понравился, а нарезка полосками показалась слишком шумной». Плейсхолдер исчезает, как только поле получает фокус (`textarea:focus::placeholder { color: transparent }`).
- Под полем справа счётчик «0 / 500» моноширинным шрифтом.
- Кнопка «Готово»: залита цветом текста, текст цвета фона, форма капсулы, высота от 48 px. Неактивна, пока не выбрана оценка.
- После нажатия «Готово» форма сменяется блоком с результатом: «4 из 5 · Скорее да», заметка (если есть) и кнопка «Изменить». «Изменить» возвращает форму с заполненными значениями.
- Если оценка уже сохранена, при открытии страницы сразу показывается блок с результатом.

### 5.7. Подвал

Мелким приглушённым текстом: «Прогресс хранится только в этом браузере». Справа ссылка-кнопка «Начать заново». По нажатию рядом появляется подтверждение «Стереть все оценки?» с кнопками «Стереть» и «Отмена». Системные диалоги `confirm()` не использовать.

## 6. Картинки-примеры

- Автор кладёт файлы в `public/examples/`, имя — `{id}.webp` (например, `glitch.webp`).
- Рекомендация для автора: webp, ширина 2000 px, пропорция 16:7 или 16:9.
- Путь строится через `import.meta.env.BASE_URL`, чтобы работал на GitHub Pages.
- Добавь в репозиторий `public/examples/README.md` с этими правилами.

## 7. Визуальный стиль

Чисто и минималистично: много воздуха, тонкие линии вместо рамок и плашек, один шрифт, цвет только в метке оси. Ориентир — утверждённый макет.

### 7.1. Цвета

| Токен | Светлая | Тёмная |
|---|---|---|
| `--bg` фон | `#FBFBFC` | `#121214` |
| `--fg` текст | `#111114` | `#EDEDF0` |
| `--muted` приглушённый текст | `#65676F` | `#9C9DA6` |
| `--line` линии и рамки | `#E3E4E9` | `#2B2B31` |
| `--surface` карточки промтов, поле заметки | `#F1F2F5` | `#1B1B1F` |
| `--plate` заглушка картинки | `#E9EAEE` | `#1E1E23` |

Цвета осей (точка у метки оси):

| Ось | Светлая | Тёмная |
|---|---|---|
| Цвет | `#E8318A` | `#FF4FA3` |
| Фактура | `#F2541B` | `#FF7442` |
| Форма | `#2B3FE0` | `#6B7BFF` |
| Композиция | `#7FA80F` | `#C6E832` |

Все цвета задаются только через CSS-переменные в `styles/tokens.css`. Тёмная тема переопределяет переменные под `[data-theme="dark"]`.

### 7.2. Типографика

- Onest 400/500/600. Заголовок приёма 600, межбуквенный интервал −0.045em, межстрочный 0.95.
- Основной текст 17 px, межстрочный 1.6.
- Подписи разделов 14 px, вес 500, приглушённый цвет.
- JetBrains Mono 13–13.5 px для промтов, счётчика и «приём N / 12».

### 7.3. Раскладка

- Контент по центру, максимальная ширина 1040 px, боковые отступы не меньше 16 px (на телефоне) и 24 px (на десктопе).
- Отступ сверху до заголовка приёма около 88 px, между крупными разделами 40–72 px.
- Скругления: 4 px у картинки и карточек промтов, 8 px у поля заметки, капсулы у кнопок.
- Тени не использовать.

### 7.4. Доступность и качество

- Работает от 360 px ширины без горизонтальной прокрутки.
- Видимый фокус у всех интерактивных элементов.
- Контраст текста не ниже WCAG AA в обеих темах.
- Тон текстов: на «ты», просто, без восклицательных знаков.

## 8. Деплой на GitHub Pages

- Workflow `.github/workflows/deploy.yml`: при пуше в `main` собирает проект и публикует папку `dist` через `actions/deploy-pages`.
- `base` в `vite.config.ts` равен `/<имя-репозитория>/`. Имя берётся из переменной окружения, по умолчанию — из имени репозитория.
- `README.md` на русском: что это за проект, как запустить локально (`npm install`, `npm run dev`), как включить GitHub Pages в настройках репозитория (Settings → Pages → Source: GitHub Actions), как добавить новый приём и картинку.

## 9. Не делать в первой версии

- Карту курса со списком всех приёмов.
- Итоговый и промежуточный портрет визуального языка.
- Экспорт и импорт прогресса.
- Аккаунты, загрузку работ, аналитику, английскую версию интерфейса.

Эти функции появятся, когда будет больше приёмов. Код должен позволять их добавить: прогресс хранится по `id` приёма, приёмы читаются из общего списка.

## 10. Этапы

1. **Каркас.** Vite + React + TS, роутинг, структура папок, `techniques.json` с контентом из 4.2, типы, токены цветов и шрифты.
2. **Тема.** Переключатель, сохранение выбора, инлайн-скрипт против вспышки.
3. **Страница приёма.** Все блоки из 5.4, заглушка картинки, кнопки копирования, адаптивность.
4. **Оценка.** Хранилище с тестами, форма, блок результата, «Изменить», «Начать заново».
5. **Деплой.** Workflow, `base`, README, `public/examples/README.md`.

### Критерии приёмки

- Страница «Глитч» открывается на GitHub Pages, перезагрузка не даёт 404.
- Тема переключается, выбор сохраняется, при загрузке нет вспышки другой темы.
- Оба промта копируются кнопкой-иконкой, иконка меняется на галочку.
- Плейсхолдер в заметке исчезает при клике в поле.
- «Готово» неактивна без оценки. После нажатия и перезагрузки страницы оценка и заметка на месте.
- Без картинки вместо неё показывается рамка-заглушка, вёрстка не ломается.
- Страница выглядит аккуратно на 360 px и на 1440 px.
- Тесты хранилища проходят.
- Чтобы добавить новый приём, достаточно дописать объект в `techniques.json` и положить картинку.
